# Data Card: Flight Delay Training Sample

## 1. Назначение и запрещенные сценарии
* **Назначение:** Учебный синтетический набор данных (`flights_sample.csv`) предназначен для отработки процессов валидации данных, проверки контрактов и настройки MLOps-инфраструктуры.
* **Запрещенные сценарии:** Набор не предназначен для принятия реальных операционных решений авиакомпаний или прогнозирования задержек рейсов в реальном мире.

## 2. Происхождение и владельцы
* **Источник:** Синтетический учебный датасет для курса MLOps.
* **Владелец команды:** Команда team-2 (ответственный за карточку: @Vikabh).

## 3. Состав полей и целевая переменная
Набор содержит 24 строки и следующие поля:
* `DepHour`: целое число от 0 до 23 (час отправления по местному времени, признак).
* `IsWeekend`: признак выходного дня, строго принимает значения 0 или 1 (признак).
* `ArrDelay`: задержка прибытия в минутах, целое число от 180 до 1440 (источник для формирования целевой переменной).

> **Важно (Предотвращение утечки данных):** 
> Целевой класс формируется условием `ArrDelay > 15`. Сам исходный столбец `ArrDelay` **строго запрещено** использовать в качестве входного признака (`FEATURES`) для модели, так как это приведет к прямой утечке целевой переменной (data leakage).

## 4. Стратегия разделения данных
* Используется случайное стратифицированное разделение (`random_state=42`) с учетом баланса целевого класса.

## 5. Версионирование и конвейер данных (ЛР3)

- **Версионирование через DVC**: Исходный набор данных `data/flights_sample.csv` зафиксирован в Git и отслеживается с помощью DVC.
- **Стадии конвейера**:
  - `validate`: проверка входящих данных по контракту (`data/contract.json`).
  - `preprocess`: очистка данных и формирование бинарной целевой переменной (`ArrDelay > 15`).
  - `split`: стратифицированное разделение на обучающую (`train`) и тестовую (`test`) выборки с фиксированным `random_state=42`.
- **Предотвращение утечек данных (Data Leakage)**:
  - Целевая колонка `ArrDelay` строго исключена из списка входных признаков (`FEATURES`).
  - Масштабирование признаков (scaler) обучается **исключительно на тренировочной выборке (`train`)** и применяется к тесту через сохраненный объект `models/scaler.pkl`, чтобы исключить утечку информации из тестового набора.

# Data Card: Отчисление студентов (`students_sample.csv`, ЛР4, вариант 10)

## 1. Назначение и запрещённые сценарии
* **Назначение:** Синтетический учебный набор данных (`data/students_sample.csv`) предназначен для проведения сравнимых экспериментов в MLflow по прогнозированию риска отчисления студентов в рамках ЛР4 (сегмент `students/`).
* **Запрещённые сценарии:** Данные являются искусственно сгенерированными (синтетика) и **не предназначены** для принятия реальных административных решений в вузах, отчисления студентов или оценки работы реальных кураторов.

## 2. Происхождение, объём и контроль целостности
* **Источник:** Синтетический набор данных, сгенерированный воспроизводимым скриптом `scripts/generate_students.py`.
* **Владелец и ответственный за карточку:** Команда `team-2` (@Vikabh).
* **Объём и формат:** 1200 строк, все столбцы целочисленные (`int`), размер файла — `39 292` байта.
* **Контроль версии данных:**
  * Контрольная сумма **SHA-256**: `3128fe6b8c6e7cd67d34597fe14b87312a56461a2531585d8f6bf285e849eadb` (автоматически вычисляется из файла и фиксируется тегом `data_sha256` во всех запусках MLflow).
  * Схема и допустимые диапазоны значений проверяются контрактом `data/students_contract.json` (версия `2.0.0`) на стадии `validate`.

## 3. Состав полей и целевая переменная
* **Целевая переменная (`Target`):** многоклассовая классификация (3 класса):
  * `0` — **Dropout** (отчисление): **28,4 %**
  * `1` — **Enrolled** (продолжает обучение): **14,3 %**
  * `2` — **Graduate** (выпускник, мажоритарный класс): **57,3 %**
* **Признаки ранней конфигурации (`early`, момент зачисления — `enrollment`):**
  * `Age` — возраст при зачислении;
  * `Gender` — пол;
  * `DaytimeAttendance` — форма обучения (дневная/вечерняя);
  * `Scholarship` — наличие стипендии;
  * `PrevGrade` — оценка предыдущего образования;
  * `AdmissionGrade` — вступительный балл.
* **Дополнительные признаки поздней конфигурации (`late`, после 2-го семестра — `after_sem2`):**
  * `Sem1Enrolled`, `Sem1Approved`, `Sem1Grade` — количество выбранных, сданных дисциплин и средняя оценка за 1-й семестр;
  * `Sem2Enrolled`, `Sem2Approved`, `Sem2Grade` — количество выбранных, сданных дисциплин и средняя оценка за 2-й семестр.

## 4. Стратегия разделения и конвейер данных (ЛР4)
* **Разбиение:** Стратифицированное разделение по `Target` на обучающую (80 %) и тестовую (20 %) выборки (`test_size = 0.2`, `random_state = 42`).
* **Независимость от ЛР3:** Данные и артефакты обрабатываются в изолированном конвейере `students/dvc.yaml` и не затрагивают `data/flights_sample.csv`.

## 5. Риски, ограничения и предотвращение утечек
* **Дисбаланс классов:** Миноритарный класс `Enrolled` составляет всего 14,3 %, а мажоритарный `Graduate` — 57,3 %. Использование `weighted-F1` скрывает ошибки на редком классе, поэтому основной метрикой принята `macro-F1`, а в модели применяется `class_weight="balanced"` (см. ADR 0002).
* **Временная утечка (Temporal Leakage):** Семестровые показатели (`Sem1*`, `Sem2*`) из поздней конфигурации недоступны на момент зачисления. Использование поздней модели для раннего оповещения куратора некорректно (см. ADR 0003).
* **Утечка данных (Data Leakage) при предобработке:** Целевой столбец `Target` исключается из матрицы признаков `X` на стадии `preprocess`; стандартизация признаков (`StandardScaler`) выполняется внутри единого `Pipeline` и обучается строго на `train`.
* **Синтетическая природа данных:** Зависимости в данных отражают заданную генератором модель и могут не совпадать с реальными распределениями студенческих когорт.
