# ADR 0003: Конфигурация признаков по умолчанию в ветке main (ЛР4)

- **Статус:** Принято
- **Дата:** 2026-11-03
- **Автор:** Documentation and risk reviewer
- **Контекст:** Лабораторная работа №4, вариант 10 («Отчисление студентов», сегмент `students/`).

## Контекст и постановка задачи

В рамках эксперимента в сегменте `students/` сравниваются две конфигурации признаков для прогнозирования отчисления студентов:

1. **Ранняя конфигурация (`features.config = early`, `prediction_moment = enrollment`):**  
   Признаки, доступные непосредственно в момент зачисления абитуриента: `Age`, `Gender`, `DaytimeAttendance`, `Scholarship`, `PrevGrade`, `AdmissionGrade`.
2. **Поздняя конфигурация (`features.config = late`, `prediction_moment = after_sem2`):**  
   Все признаки ранней конфигурации плюс показатели успеваемости за первый и второй семестры: `Sem1Enrolled`, `Sem1Approved`, `Sem1Grade`, `Sem2Enrolled`, `Sem2Approved`, `Sem2Grade`.

Поздняя конфигурация закономерно может демонстрировать более высокие значения `macro-F1` за счёт информации о реальной сдаче сессий, однако на этапе зачисления эти данные ещё не существуют. Необходимо зафиксировать, какая конфигурация используется в конвейере `students/params.yaml` в ветке `main` по умолчанию.

## Рассмотренные варианты

* **Вариант A — Оставить в `main` позднюю конфигурацию (`late`):**  
  Даёт максимальную метрику качества на тестовой выборке, но делает модель неприменимой для раннего выявления группы риска при зачислении (возникает временная утечка относительно реального сценария использования куратором).
* **Вариант B — Зафиксировать в `main` раннюю конфигурацию (`early`) по умолчанию:**  
  Использует исключительно признаки, известные на момент зачисления (`enrollment`), что соответствует прикладной задаче раннего предупреждения отчисления, при сохранении `late` в `students/params.yaml` как сравниваемого варианта эксперимента.

## Принятое решение

1. **Конфигурацией по умолчанию в `students/params.yaml` в ветке `main` выбирается ранняя конфигурация (`features.config: early`, `prediction_moment: enrollment`).**
2. **Причина выбора:** Главная прикладная ценность модели для куратора — выявить студентов группы риска в начале обучения, когда ещё можно своевременно предложить академическую поддержку. Прогноз после 2-го семестра (`late`), даже при более высоком `macro-F1`, запаздывает для раннего вмешательства.
3. **Сохранение воспроизводимости сравнения:** Список признаков поздней конфигурации (`features.late`) сохраняется в `students/params.yaml`, чтобы любой участник или проверяющий мог воспроизвести оба запуска в MLflow (`logreg-early-seed42` и `logreg-late-seed42`) и сравнить их через `dvc metrics diff` и `scripts/compare_runs.py`.
4. **Разделение выводов в отчётах:** В отчёте сравнения и `README.md` результаты разделяются на два независимых вывода: «лучшее качество на тесте» и «пригодно для раннего сигнала».

## Последствия

* Стадия `preprocess` по умолчанию отбирает 6 признаков этапа зачисления (`early`) и целевую переменную `Target`, не перезапуская стадию валидации исходного датасета (`validate`).
* Если в ходе эксперимента `late` покажет статистически значимый прирост (по критерию ADR 0002), это фиксируется как цена раннего прогноза, но конфигурация по умолчанию в `main` не меняется без отдельного пересмотра прикладного сценария.
