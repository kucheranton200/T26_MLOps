## Проверка работы коллег
Ревью чужих PR по ЛР3 я не оставлял. Работу коллег проверил воспроизведением их конвейера (PR #52, #54, #56) на своей машине после `git pull` main.

Что нашёл: на Windows после первого `dvc repro` `git status` показывает изменённые `dvc.lock` и `reports/metrics.json`, хотя метрики и хэши входов совпадают с закоммиченными. `git ls-files --eol` показал у этих файлов `w/crlf` при `i/lf` в репозитории, то есть конвейер записывает текстовые файлы с CRLF. Хэши бинарных `models/model.pkl` и `models/scaler.pkl` тоже отличаются, предположительно из-за версий библиотек, но это я не проверял. Файл `.gitattributes` на это не влияет, потому что он задаёт окончания строк только для репозитория. Изменения `dvc.lock` после запуска я не коммитил и откатил командой `git restore`. Проблема описана в релизной записке и в карточке @Z0rko32.

## Воспроизведение
Окружение: Windows, PowerShell, Python 3.12.10, `.venv`, `core.autocrlf=false`, dvc 3.67.1, scikit-learn 1.9.1, numpy 2.5.4, чистое дерево Git.

```
python -m pip install -e ".[dev,data]"
dvc repro
dvc repro
dvc status
dvc metrics show
python -m ruff check .
python -m pytest -q
```

- Первый `dvc repro`: `validate` пропущена (её отчёт в Git), `preprocess`, `split`, `train`, `evaluate` выполнены.
- Второй `dvc repro`: пропущены все пять стадий, `Data and pipelines are up to date.`
- `dvc status`: `Data and pipelines are up to date.`
- Метрики: roc_auc 0,666667, f1 0,5, brier_score 0,228108, accuracy 0,6, n_test 5.
- `ruff` без замечаний, `pytest`: 29 тестов пройдено.

## Контрольный сценарий: изменение параметра
В `params.yaml` значение `train.C` изменено с 1,0 на 0,5. Ожидание: перезапустятся только зависимые стадии.

- `dvc status` показал изменение только в `train`.
- `dvc repro` пропустил `validate`, `preprocess`, `split` и выполнил `train` и `evaluate`.
- `dvc params diff`: `train.C` 1,0 → 0,5.
- `dvc metrics diff`: изменилась только `brier_score`, 0,22811 → 0,23111.

После проверки `params.yaml`, `dvc.lock` и `reports/metrics.json` возвращены командой `git restore`, изменения не коммитились.

## Обоснование
- Параметр `train.C` выбран потому, что он входит только в раздел `train`: так сразу видно, что DVC не перезапускает лишние стадии.
- Метрики посчитаны на 5 тестовых строках, поэтому они показывают только работоспособность конвейера, а не качество модели.
- Расхождение хэшей на Windows не означает, что конвейер невоспроизводим: входы и метрики совпали. Но «чистый» `git status` после запуска на Windows не гарантирован, это записано в ограничениях релиза.
- Конвейер построен на демонстрационном варианте (задержка рейсов). Для варианта 10 недостающие части ЛР3 (две конфигурации признаков, сравнение через `dvc metrics diff`, решение в ADR) выполняются в ЛР4 отдельным конвейером в папке `students/`, не меняя конвейер ЛР3 и этот тег.
