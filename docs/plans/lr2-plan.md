## Порядок работы

1. У каждого участника своя issue с критериями приёмки.
2. Работа идёт в ветках, в main только через pull request, в описании `Closes #N`.
3. В описании итогового PR: версия контракта, команда успешной проверки, два негативных сценария, SHA-256 образца, стратегия разделения.
4. Merge после зелёного CI и review другого участника.
5. Tag lr2-v1 ставится после merge всех PR.
