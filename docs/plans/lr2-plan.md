## Порядок работы

1. У каждого участника своя issue с наблюдаемым результатом и критериями приёмки.
2. Работа идёт в ветках `lab2/<название>` от свежего main. В main только через pull request, в описании `Closes #N`.
3. Merge после зелёного CI и одобрения другого участника.
4. Tag lr2-v1 ставится после merge всех pull request.
5. Описание Release: источник данных, версия контракта, команда успешной проверки, два негативных сценария, SHA-256 образца, стратегия разделения, ограничения и отложенные задачи для ЛР3.

## Зависимости и риски

- Тесты опираются на контракт и интерфейс валидатора (команда запуска и поля отчёта из методички). Тесты пишутся параллельно с валидатором по этому интерфейсу, стыковка в чт вечером.
- Валидатор опирается на контракт: контракт открывается в PR до чт 12:00.
- Раздел про утечку находится в docs/data-card.md и пишется тем же автором, что и карточка, поэтому конфликта правок нет.
- Нет ответа от участника до срока своей задачи: задача переходит координатору или @kucheranton200 по договорённости.
