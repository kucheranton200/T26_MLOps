## 1. Цель и границы работы

Построить и верифицировать изолированную пирамиду автоматических тестов для конвейера варианта 10 (`students/`) и модулей `src/mlops_project/students/`:
1. **Пирамида тестов**:
   - **Unit-слой**: чистые функции валидации, метрик и преобразований.
   - **Contract-слой**: параметризованные тесты схемы данных (`data/students_contract.json`) на изолированных временных выборках (`tmp_path`).
   - **Model-слой**: инварианты артефакта модели skops (`students/models/model.skops`), форма выхода `(N, 3)`, вероятности в $[0, 1]$, проверка детерминированности обучения.
   - **Integration-слой**: сквозной smoke-тест полного пути `validate -> preprocess -> split -> train -> load -> predict` на фикстурах.
2. **Defect Injection**: каждый участник команды готовит и документирует один контролируемый дефект, подтверждает падение конкретного теста по его `node ID`, сохраняет фрагмент отчёта и восстанавливает работоспособность.
3. **Отчётность**: формирование машинного отчёта `reports/tests/lr5-pass.xml` (JUnit XML), сводной таблицы «риск — тест — ожидаемый сигнал», персональных Evidence cards и тега `lr5-v1`.

### Границы:
- Тесты не зависят от внешних серверов, сети или запущенного сервера MLflow (все интеграционные тесты используют файловые пути и локальный backend).
- Эталонный датасет `data/students_sample.csv` остаётся неизменным (тесты создают модифицированные выборки исключительно через fixture `tmp_path`).
- Контейнеризация и Docker в ЛР5 не входят (запланированы на ЛР6).

## 4. Договорённости по интерфейсу и архитектуре тестов

1. **Изоляция и воспроизводимость**:
   - Любой тест, создающий или меняющий данные, обязан использовать фикстуру `tmp_path`.
   - Файлы `data/students_sample.csv` и `data/students_contract.json` доступны только для чтения.
   - Тесты не должны требовать поднятого сервера MLflow (флаг `--mlflow` для unit/smoke тестов отключён либо замокан).
2. **Структура фикстур (`tests/conftest.py`)**:
   ```python
   from pathlib import Path
   import pandas as pd
   import pytest

   @pytest.fixture
   def valid_students_frame() -> pd.DataFrame:
       return pd.read_csv(Path("data/students_sample.csv"))

   @pytest.fixture
   def students_csv_factory(tmp_path: Path):
       def create_csv(df: pd.DataFrame, filename: str = "students_modified.csv") -> Path:
           path = tmp_path / filename
           df.to_csv(path, index=False, lineterminator="\n")
           return path
       return create_csv
   ```
3. **Параметризация негативных кейсов**:
   Каждый параметризованный тест сопровождается человекочитаемым `ids`, чтобы в отчёте сразу было видно условие отказа:
   ```python
   @pytest.mark.parametrize(
       ("col", "val", "expected_msg"),
       [
           ("Age", -1, "Age: value must be >= 17"),
           ("Target", 5, "Target: value not in allowed set {0, 1, 2}"),
           ("Scholarship", 2, "Scholarship: binary flag expected"),
       ],
       ids=["negative_age", "invalid_target_class", "non_binary_scholarship"]
   )
   ```
4. **Инварианты модели skops**:
   - Модель загружается через `skops.io.load` с доверенными типами.
   - Метод `predict_proba` возвращает массив размерности `(len(X), 3)`.
   - Сумма вероятностей по строкам равна $1.0 \pm 10^{-5}$.
   - Список признаков в модели точно совпадает со списком ранней или поздней конфигурации.

## 9. Зависимости и риски

- **Связь с ЛР4**: Работа в ветках ЛР5 и слияние плана ЛР5 разрешены только после проставления тега `lr4-v1`.
- **Изоляция окружения**: Тесты не должны создавать артефактов в корневом каталоге проекта. Все промежуточные CSV и skops-файлы должны создаваться исключительно внутри `tmp_path`.
- **Предотвращение ложноположительных тестов**: Запрещены проверки без явных `assert` или `pytest.raises`. Каждый тест должен проверять конкретное диагностическое сообщение.
- **Откат дефектов**: Ни один контролируемый дефект из раздела Defect Injection не должен попасть в коммиты, вливаемые в `main`.
